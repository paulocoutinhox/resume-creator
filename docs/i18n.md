# Internationalization

Fixed UI labels live in `modules/i18n/locales/<locale>.yml`. Each locale catalog must define every key — missing keys raise a `TranslationError` (no silent fallback to the key name).

Currently supported locales: `en`, `pt`.

## Adding a new locale

1. Add the new value to the `Locale` enum in `modules/models/enums.py`.
2. Add the matching Babel locale code in `modules/utils/dates.py` (`_BABEL_LOCALE`).
3. Create `modules/i18n/locales/<code>.yml` mirroring every key from the existing catalogs.
4. Add the language to `site.languages` in `data/config.yml` and provide the corresponding `data.<code>` block.

## Per-language data

Every locale declared in `site.languages` must have its own entry under `data:` in `data/config.yml`. Each entry is the **path to a YAML file** (relative to `config.yml`'s directory) holding the full `LocalizedResume` block (profile, professional, social, languages, experience, education, certifications, side_projects, open_source_projects):

```yaml
data:
  en: locales/en.yml
  pt: locales/pt.yml
```

This keeps `config.yml` focused on site-level settings and lets each language live in its own file under `data/locales/`. The schema validator rejects configurations missing a localized file or referencing one that does not exist.

Inline mappings under `data:` are also accepted by the loader, but the recommended layout is one file per locale.

List sections **experience**, **education**, **certifications**, **side_projects** and **open_source_projects** each support an optional `bullets` array of strings on every entry (same idea as achievement bullets at work). See [experience.md](experience.md), [education.md](education.md), [certifications.md](certifications.md), [side-projects.md](side-projects.md) and [open-source-projects.md](open-source-projects.md).
